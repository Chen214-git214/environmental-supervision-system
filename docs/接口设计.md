# 东软环保公众监督系统接口设计文档

## 1. 通用约定

基础地址：`http://localhost:8080`

请求数据格式：`application/json`

统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 1.1 认证方式

除登录接口与公众端接口外，所有接口都必须在请求头携带 JWT：

```text
Authorization: Bearer <token>
```

令牌由登录接口签发，采用 HS256/HS384 对称签名，载荷包含用户编号（`uid`）、角色（`role`）与过期时间（`exp`）。校验失败时统一返回：

| HTTP 状态 | code | 含义 |
| --- | --- | --- |
| 401 | 401 | 未携带令牌、令牌无效或已过期 |
| 403 | 403 | 身份合法，但当前角色无权访问该接口 |

接口权限划分：

| 路径前缀 | 允许角色 |
| --- | --- |
| `/api/auth/**`、`POST /api/public-supervisors` | 公开（无需令牌） |
| `/api/feedback/**`、`/api/statistics/**` | 管理员 |
| `/api/grid/**` | 网格员 |
| `/api/public-feedback/**`、`/api/public-supervisors/me` | 公众监督员 |
| `/api/grid-cities`、`/api/aqi-levels` | 管理员 / 网格员 / 公众监督员（三种角色都需要选城市与级别） |
| `/api/air-quality-stats` | 管理员 / 网格员 / 公众监督员 |

### 1.2 管理员登录

接口地址：`/api/auth/admin/login`

请求方式：`POST`

鉴权：公开。账号读取自 `sys_admin` 表，密码以 BCrypt 摘要校验；登录成功会更新 `last_login_time`。

请求示例：

```json
{
  "adminCode": "admin",
  "password": "123"
}
```

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzM4NCJ9...",
    "adminInfo": {
      "id": 1,
      "adminCode": "admin",
      "name": "系统管理员"
    }
  }
}
```

> `name` 取自 `sys_admin.real_name`；账号被停用（`status = 0`）时返回「该管理员账号已被停用」。
> 处理反馈时记录的处理人编号即此处的 `id`，反馈详情中的 `handlerName` 亦取自该表。

请求方式：`POST`

请求示例：


响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzM4NCJ9...",
    "gridMemberInfo": {
      "gridMemberId": 1,

```

> 说明：网格员相关接口（`/api/grid/**`）不再通过请求参数接收 `gridMemberId`，上报人身份由令牌解析得到。

### 1.5 公众监督员注册

> 注册接口本身公开（用户尚无账号），注册成功后同样返回令牌，前端可直接进入反馈提交流程。
> 响应结构见 1.4，`data` 中为 `token` 与 `supervisorInfo`。

## 2. 公众监督员注册

功能描述：公众监督员提交注册信息，系统创建公众监督员账号并签发登录令牌。

接口地址：`/api/public-supervisors`

请求方式：`POST`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 登录账号，4-50 位，全局唯一 |
| `password` | string | 是 | 登录密码，6-32 位，服务端以 BCrypt 摘要存储 |
| `realName` | string | 是 | 姓名 |
| `phone` | string | 是 | 手机号，需为 11 位且全局唯一 |
| `idCard` | string | 否 | 身份证号，18 位或 15 位 |

请求示例：

```json
{
  "username": "supervisor001",
  "password": "123456",
  "realName": "张三",
  "phone": "13800000001",
  "idCard": "210102199901010011"
}
```

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzM4NCJ9...",
    "supervisorInfo": {
      "supervisorId": 1,
      "username": "supervisor001",
      "realName": "张三",
      "phone": "13800000001",
      "status": 1
    }
  }
}
```

## 3. 公众监督员数据提交

功能描述：公众监督员发现空气污染问题后，提交污染类型、地点、描述和现场图片等监督反馈数据。

接口地址：`/api/public-feedback`

请求方式：`POST`

鉴权：需要公众监督员令牌（`Authorization: Bearer <token>`）。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `cityId` | number | 是 | 所属城市 ID |
| `levelId` | number | 否 | 初步空气质量级别 ID |
| `pollutionType` | string | 是 | 污染类型，如烟尘、异味、扬尘 |
| `address` | string | 是 | 详细地址 |
| `longitude` | number | 否 | 经度 |
| `latitude` | number | 否 | 纬度 |
| `description` | string | 是 | 问题描述 |
| `imageUrl` | string | 否 | 图片地址 |

> 提交人（`supervisorId`）由令牌解析得到，**不再作为请求参数传入**，避免以他人身份提交反馈。

请求示例：

```json
{
  "cityId": 1,
  "levelId": 3,
  "pollutionType": "扬尘",
  "address": "沈阳市和平区南京北街100号",
  "longitude": 123.414662,
  "latitude": 41.799921,
  "description": "施工现场未覆盖防尘网，扬尘明显。",
  "imageUrl": "https://example.com/images/feedback-1.jpg"
}
```

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "feedbackId": 1,
    "supervisorId": 1,
    "cityId": 1,
    "pollutionType": "扬尘",
    "status": 0,
    "submittedAt": "2026-06-05T09:30:00"
  }
}
```

## 4. 查询公众监督反馈列表

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `cityId` | number | 否 | 城市 ID |
| `status` | number | 否 | 状态：0 待处理，1 处理中，2 已处理，3 已驳回 |
| `page` | number | 否 | 页码，从 1 开始 |

响应示例：

## 5. 处理公众监督反馈

功能描述：管理员对公众监督反馈进行处理，更新处理状态并填写处理回复。

接口地址：`/api/public-feedback/{feedbackId}/handle`

请求方式：`PUT`

鉴权：需要管理员令牌。处理人由令牌解析得到，**不再通过请求参数传入 `handlerAdminId`**。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `feedbackId` | number | 是 | 路径参数，反馈 ID |
| `status` | number | 是 | 处理后状态：2 已处理（办结），3 已驳回 |
| `reply` | string | 是 | 处理回复，最长 500 字 |

状态机约束：仅允许 `待处理(0)` / `处理中(1)` → `已处理(2)` 或 `已驳回(3)`；
已是终态的反馈再次处理会返回 400，避免重复处理与状态回退；`status` 只接受 2 或 3。

请求示例：

```json
{
  "status": 2,
  "reply": "已通知属地网格员核查，现场已完成整改。"
}
```

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "feedbackId": 1,
    "status": 2,
    "statusText": "已完成",
    "reply": "已通知属地网格员核查，现场已完成整改。",
    "handlerAdminId": 1,
    "handlerName": "系统管理员",
    "handledAt": "2026-06-05T10:20:00",
    "assignedAt": "2026-06-05T09:40:00",
    "measuredAt": "2026-06-05T10:05:00"
  }
}
```

> 处理结果会写入反馈记录的 `admin_id` / `reply_content` / `handle_time`，
> 公众监督员可通过 `GET /api/public-feedback/mine` 看到处理状态与回复。

## 6. 网格员任务与实测数据

### 6.1 待办任务列表

接口地址：`/api/grid/tasks`

请求方式：`GET`

鉴权：需要网格员令牌。**网格员身份由令牌解析，请求参数不再传 `gridMemberId`。**

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | number | 否 | 按状态筛选，不传返回全部 |

### 6.2 任务详情

接口地址：`/api/grid/tasks/{afId}`

请求方式：`GET`

鉴权：需要网格员令牌，且该任务必须指派给当前网格员，否则返回 400「当前任务未指派给该网格员」。

### 6.3 提交实测数据

接口地址：`/api/grid/tasks/{afId}/measurements`

请求方式：`POST`

鉴权：需要网格员令牌。

请求参数（**只提交浓度值**）：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `so2Value` | number | 是 | SO2 实测浓度，单位 μg/m³ |
| `coValue` | number | 是 | CO 实测浓度，单位 mg/m³ |
| `pm25Value` | number | 是 | PM2.5 实测浓度，单位 μg/m³ |

请求示例：

```json
{
  "so2Value": 60,
  "coValue": 3.5,
  "pm25Value": 82
}
```

响应示例（等级与 AQI 由服务端计算并回填）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "afId": 1,
    "status": 1,
    "statusText": "处理中",
    "so2Level": "良",
    "coLevel": "良",
    "pm25Level": "轻度污染",
    "aqiValue": 109,
    "aqiLevel": "轻度污染",
    "measuredAt": "2026-06-05T10:05:00"
  }
}
```

计算规则：按各污染物浓度限值分段做线性插值得到单项 IAQI，取三者最大值作为 AQI，
再按 `aqi_level` 表的 `min_aqi` / `max_aqi` 定级。
**客户端提交的等级字段会被忽略**，避免上报方自行判定空气质量等级。

状态说明：实测提交后反馈仍为「处理中」，需管理员通过 `PUT /api/feedback/{afId}/handle` 办结或驳回后进入终态；
已完成实测的任务重复提交会返回 400。

## 7. 查询空气质量监测数据统计

功能描述：查询网格员上报的实测数据。数据来源为 **`air_quality_stat` 表**（一次实测一行），城市、网格员、时间范围三个条件均可选。

接口地址：`/api/air-quality-stats`

请求方式：`GET`

鉴权：需要令牌（管理员 / 网格员 / 公众监督员均可）。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `cityId` | number | 否 | 城市 ID |
| `gridMemberId` | number | 否 | 上报网格员编号 |
| `startTime` | string | 否 | 开始时间（按监测时间筛选），格式：`yyyy-MM-dd HH:mm:ss` |
| `endTime` | string | 否 | 结束时间，格式：`yyyy-MM-dd HH:mm:ss` |

约定：`startTime` 晚于 `endTime` 时返回 400「开始时间不能晚于结束时间」。

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "statId": 1,
      "feedbackId": 1,
      "cityId": 1,
      "cityName": "沈阳市",
      "gridMemberId": 1,
      "gridMemberName": "刘强",
      "levelId": 3,
      "levelName": "轻度污染",
      "aqi": 109,
      "pm25": 82,
      "pm10": 120,
      "so2": 60,
      "no2": 45,
      "co": 3.5,
      "o3": 88,
      "monitoredAt": "2026-06-05T09:00:00"
    }
  ]
}
```

> `feedbackId` 为该次实测对应的反馈编号：一条反馈可对应多条监测数据（复测）。
> 六项浓度中 `pm10`/`no2`/`o3` 按设计书存库，当前不参与 AQI 计算（AQI 取 SO2/CO/PM2.5）。

接口地址：`/api/aqi-levels`

请求方式：`GET`

鉴权：需要令牌（三角色均可）。

响应示例：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "levelId": 1,
      "levelName": "优",
      "minAqi": 0,
      "maxAqi": 50,

      "suggestion": "各类人群可正常活动。"
    }
  ]
}
```
